Audit of the working tree on 6 September 2026

The best opportunity is to improve what the student learns from its supervision before increasing the backbone. There are also confirmed evaluation/export defects that must be fixed before measuring a new method. Three research directions below could support separate papers, but their accuracy gains and novelty remain experimental questions; none is a guaranteed CVPR contribution.

Scope: inspected the current MHR-only trainer, DDP driver, augmentation and conversion code, evaluation, inference/export, available run configurations/results, and relevant primary research. Existing uncommitted changes were included in the audit and preserved. Numerical probes ran on CPU with the local TorchScript rig, local annotations, and the epoch-137 EMA checkpoint b3_s1. CUDA was unavailable to this process, so there was no new GPU timing, distributed reproduction, or training sweep. The small probes are diagnostics, not new benchmark results.

**What the current baseline actually is.**

The active default architecture has 39,961,412 trainable parameters, verified by instantiating it: RepViT-M2.3, a four-layer decoder of width 512, and 71 queries. One query supplies all 204 MHR parameters, 45 surface-shape parameters, and three camera translations; 70 queries supply the auxiliary/deployed 2D output. Self-attention allows those queries to help the global query, so their presence does not prove wasted capacity. The released model's 17M/9-query description and approximately 5 ms timing are not measurements of this current pipeline.

The stored report `benchmark/results/3dpw_test_b3_s1_teacher_adapter.json` records 41.825 mm J14 PA-MPJPE and 69.030 mm root-relative MPJPE on 35,463 test person-frames, with zero dropped predictions. These are existing results, not rerun results. Training used rebalanced losses, so loss rebalance is already part of that baseline. The README's later 41.71 claim is not the value in this report; identify exact checkpoint, adapter and preprocessing hashes before quoting a baseline.

**Confirmed implementation problems, ordered by priority.**

1. **Standalone export silently removes scale bounds.** `tools/pth_to_onnx.py:116` constructs the default configuration, where bounds are off; line 128 loads with `strict=False`, and unexpected keys only print a message. A bounded model's `scale_lo` and `scale_hi` are therefore ignored. Reproducing this exact reload pattern produced no missing keys, two unexpected keys, and a maximum MHR-output difference of 0.288254 on the same input, before any ONNX conversion. This used newly initialized models with identical loaded weights, isolating the configuration defect; it is not a measured deployed checkpoint error. Restore the saved architecture/configuration, reject unexpected model keys, and compare all exported outputs with the original configured model on real crops.

2. **Focal conditioning is not carried through evaluation and deployment.** `benchmark/eval_3dpw_ckpt.py:97` creates a default config; its dataset construction at line 109 does not enable `cliff_focal`. Bounded checkpoints instead fail strict loading because the evaluator has no corresponding buffers. `instanthmr/pipeline.py:98` does not pass focal calibration into `InstantHMR`. Even direct use of `InstantHMR(focal=...)` returns the diagonal-image heuristic in `HMRPrediction.focal_length` at `instanthmr/inference.py:256` and in the batch path. Training validation does pass the new flag. Consequently the documented equality of all evaluation paths only holds for compatible older configurations. Store preprocessing mode independently of whether intrinsics are known, serialize intrinsics/config metadata, and test training-validation/checkpoint/ONNX parity.

3. **The v2 crop-center update omits division by zoom.** `train_distill_mhr_only.py:678` uses `cx -= dx * crop_w / 2` and similarly for y. With zero roll, the image transform is `u' = s(u-center) + center + translation`; its inverse puts the crop center at `center - translation/s`. The conditioning update requires that same `/s`. On a real MPII crop of width 996 pixels, scale 2 and dx 0.20, the code supplies center 1101.4 instead of 1151.2: a 49.8-pixel discrepancy. This is a controlled augmentation probe, not an estimate of mean dataset error. Derive conditioning from the complete inverse affine transform, including rotation and flip, instead of separate manual corrections.

4. **The new camera representation remains approximate for unequal fx/fy.** `train_distill_mhr_only.py:704` uses fy for both axes. A camera with diagonal focal matrix F does not in general satisfy `R F = F R`; rotating pixels and rotating 3D with an unchanged anisotropic camera are different operations. A synthetic fx=1000, fy=500, 30-degree roll example gives 44.88 pixels of disagreement. This does not establish an error of that size in the actual corpus: sampled COCO/AIC/MPII focals had equal axes, and a separate 128-sample Harmony4D probe found fx/fy between 0.99393 and 1.03757. This is a smaller, conditional concern in the available data. Carry full transformed intrinsics/rays or rectify to square pixels. Existing counter-rotation in the reprojection loss avoids claiming that its forward/reverse algebra itself is broken; the issue is the physical consistency and information content of the input representation.

5. **Validation can reward a model that fails on hard frames.** `val3dpw.py:179` removes non-finite predictions before calculating accuracy. Logging a drop count does not prevent checkpoint selection on the easier surviving subset. Mark such a checkpoint invalid for selection, or explicitly define a fixed-population failure metric. `train_distill_jz.py:120` also averages rank means and counts rather than reducing error sums and valid counts. That is slightly inaccurate for uneven shards and potentially worse when failure counts differ. The existing b3_s1 report has zero drops, so this is a vulnerability in selection, not evidence its stored result was inflated this way.

6. **Recovery bookkeeping overstates successful updates.** In both regular and fallback paths, the driver calls the scheduler and EMA after `GradScaler.step` without checking whether gradient overflow skipped the optimizer update (`train_distill_jz.py:715`, `:793`). A finite loss does not imply finite gradients. Likewise, finite non-FK losses are not mathematically bounded: squared parameter error and cross-entropy can grow without bound. Make successful-update counting explicit and inspect gradient finiteness. The scale bounds and fallback remain useful safeguards; they do not by themselves certify recovery. This was established by control-flow inspection, not a GPU overflow reproduction.

**Remaining learning bottlenecks and limits on the evidence.**

- **Incomplete direct parameter supervision.** At the default geometric probabilities, only 20% of samples receive direct root-parameter loss. With `pose_split` enabled, local pose receives it on 60%; without it, only 20%. Flipped examples still have 3D geometric supervision, so saying they have no 3D training signal would be wrong. Correct mirrored local-transform targets and valid rotated root targets can restore direct supervision without another image encoder pass. Validate the rig's mirror mapping instead of assuming its Euler channels have SMPL's permutation/sign convention.
- **Redundant target coordinates.** The actual 889-by-204 rig transform has rank 192. A parameter displacement of norm 10 along a null direction changed skeleton positions by at most 0.000153 mm across 192 sampled annotations. Thus coordinate losses distinguish some targets that are identical for the skeleton. This verifies redundancy, not that those directions contain substantial teacher variance or explain several millimeters of error. Measure that variance and its trunk gradients before treating this as the dominant cause. Skeleton equivalence must also be checked against mesh corrective behavior before replacing exported parameters.
- **The mesh is poorly assessed by the training objective.** `MHRForwardPass.get_joints` explicitly replaces the 45 identity parameters with zeros. Perturbing supplied shape by +2 changed its skeleton by exactly zero in the probe. Shape still receives direct parameter loss, but there is no surface reconstruction loss or surface metric to establish mesh fidelity. PA-MPJPE improvement can coexist with worse body shape or hands. Add sparse surface supervision and a surface evaluation using a valid cross-topology correspondence where needed.
- **Substantial student/label discrepancy remains.** On 32 unaugmented crops from each local source, b3_s1 had body-30 PA error against annotations of 33.57 mm on COCO, 27.21 on AIC, and 33.09 on MPII. These are training-source samples, not verified individual members of the cluster's train partition. They support investigating fit/representation quality, without establishing a generalization score or proving the backbone is the cause. On a separate 192-annotation probe, the skeleton-to-keypoint approximation alone contributed 1.35 mm over 70 points and 3.14 mm over the 30 body points. It is not the whole approximately 30 mm discrepancy, but the overall 70-point average hides its larger body residual.
- **Auxiliary objectives compete for shared features.** The README reports that 2D terms account for roughly 56% of trunk gradient norms in one study and that detaching them gave a small pilot improvement. Those measurements were not independently rerun here. Critically, Gaussian-label entropy divided by total cross-entropy is not the fraction of the task that is learned: `CE=H(target)+KL(target||prediction)`, and H is a constant with zero model gradient. The quoted entropy floor does not prove 95% convergence or justify detachment. Gradient direction, variance, and matched-seed task results are the relevant evidence. Nor does one global output token alone prove a capacity bottleneck.
- **Data quantity is not useful supervision quantity.** Mixture weights depend on dataset counts. Per-keypoint observation confidence is used for 2D; the 3D objective uses fixed body/finger weights rather than sample-specific fit reliability or ambiguity. Many occluded labels are complete optimization fits, which does not mean they are visually identifiable. Do not simply remove all invisible 3D supervision: it also supplies useful pose priors. Measure error by visibility, pose rarity and label provenance, and separate uncertainty in fitted labels from uncertainty in image evidence.
- **The data loader uses stored person crops.** Original frames and optional hand crops exist in the pipeline but are not consumed by this trainer. This limits realistic crop jitter and hand detail; interpolating a 224-pixel body crop cannot restore unseen detail. Stronger augmentation should be tested against access to actual surrounding image content.

**Evaluation issues that matter for a submission.**

The local corpus is documented as containing all 3DPW sequences in `sam3d_distill_mix`; cluster-trained checkpoints are documented as using a different, clean corpus. The loader itself does not enforce this separation. Use a saved source-image/sequence manifest and explicit exclusions for validation and test, including any offline regressor/feature-cache fitting. The skeleton-to-keypoint fitter scans every supplied dataset folder, so its provenance also matters.

The fixed teacher-derived J14 adapter is preferable to fitting a different adapter per student, but it is still learned using paired 3DPW-train ground truth. Disclose that target-dataset supervision. Rotation/translation equivariance does not prove that a linear map cannot absorb systematic pose error. Test the map on held-out sequences and an external dataset or derive it from body-model correspondences. The fitting script's halfway split is not an explicit sequence grouping. Never refit on the reported split.

The harness uses GT-derived boxes, further crop expansion, a 60%-inside-image filter and its own person-frame list. Using the standard SMPL/H36M reference alone does not establish an identical published protocol. Reevaluate comparison models on the same manifest, or implement their standard protocol faithfully. Report GT boxes versus detected boxes and known versus estimated intrinsics separately. Disable recurring test-set monitoring while choosing methods: human design decisions can overfit it even if checkpoint-selection code ignores it.

PA-MPJPE removes global translation, rotation and scale. Root-relative MPJPE removes translation but still penalizes scale and orientation. Neither is a temporal consistency metric; both can detect pose errors that also cause jitter. Report camera-space accuracy, surface error, hand error, temporal acceleration error and bone-length variation when making those claims. Low acceleration alone can result from oversmoothing: compare against GT motion and report lag. The repository's documented 34–49 mm seed spread is for a different 70-keypoint metric, not a measured standard deviation of the current J14+adapter result.

**Three candidate contributions, each intended as an independent research program.**

**1. Distillation over identifiable articulated geometry.**

Hypothesis: a compact student wastes learning capacity on arbitrary choices made by fitting solvers, and receives inconsistent or missing parameter supervision under image transformations. Define an equivalence class of rig parameters that produce the same relevant geometry; supervise that class and physically meaningful local transforms instead of blindly reproducing each solver coordinate.

Start with the verified linear redundancy: for the transform A and parameter prediction p, use a normalized robust loss on `A(p_student-p_target)`, or predict its independent coordinates. Add exact transformation rules for roll and mirroring, periodic/geodesic rotation losses, and confidence that distinguishes image-observable constraints from teacher priors. Keep surface-specific information in a separately supervised residual if skeleton-equivalent parameters are not mesh-equivalent. Recover a valid bounded representative for export; naive projection followed by clipping can break equivalence.

The inexpensive baseline is transformed-coordinate loss with the deployed architecture unchanged. A 192-coordinate head plus fixed reconstruction costs about 39,000 multiply-accumulates per person; it can be fused with adjacent linear operations where there is no intervening nonlinear constraint. Target less than 10% extra training time and approximately unchanged inference; verify both rather than assuming them.

The research claim must be broader than removing 12 dimensions: demonstrate invariance to equivalent relabelings, better gradient conditioning, and improved sample efficiency across more than one rig/annotation source. Compare against raw parameter loss, geometry-only loss, normalized joint-transform loss, a pose-prior baseline and augmentation fixes alone. [MHR](https://arxiv.org/abs/2511.15586), [HybrIK](https://openaccess.thecvf.com/content/CVPR2021/html/Li_HybrIK_A_Hybrid_Analytical-Neural_Inverse_Kinematics_Solution_for_3D_Human_CVPR_2021_paper.html) and [TokenHMR](https://arxiv.org/abs/2404.16752) already cover expressive rigs, geometric inverse kinematics and pose representations; those are not new claims here.

Main risk: the redundant directions may have little actual target variance, so removing them may produce negligible accuracy gains. A cheap first experiment should compare projected and raw parameter losses with identical geometric losses and seeds. If only numerical stability improves, this remains an engineering fix rather than an independent accuracy paper.

**2. Distill the teacher features that resolve 3D ambiguity, under a fixed teacher-compute budget.**

Hypothesis: final fitted labels leave the compact encoder to rediscover difficult cues such as front/back orientation, foreshortening and occluded-limb context. The current loss contains no intermediate teacher-feature transfer. Transfer a small, body-part representation chosen for its influence on 3D pose rather than generic feature similarity or 2D localization.

On a predeclared 5–10% training subset, extract clean-image teacher part descriptors. Estimate which feature directions affect depth/articulation using the teacher decoder's output sensitivities, while separating camera and surface-shape responses. Cache a compressed descriptor and reliability information. Train small student-side projectors on corresponding part queries/features, including degraded views with correctly matched body-part identities. Retain the ordinary supervision on the full corpus. Do not assume spatially warping cached DINO features is equivalent to reencoding a rotated/occluded image.

A possible cache format is 16 descriptors × 64 channels × 2 bytes = 2,048 bytes/image: about 7.6 GB for 3.7M images, or 0.38 GB for 5%, before metadata. This is a proposed compression format, not a measured sufficient representation. Generating teacher features and sensitivities has a real offline GPU cost; report it and enforce a budget. Do not run the teacher every minibatch. Remove projectors at inference, giving exactly zero additional deployed network operations if the student architecture is kept fixed. Target no more than 20% additional total training-plus-preprocessing GPU-hours.

The publishable claim would be that pose-sensitive feature selection transfers more 3D accuracy per teacher GPU-hour than generic feature distillation. Compare equal-budget output-only transfer, ordinary feature matching, random projections, uniform versus selected examples, and simple 2D-loss attenuation/detachment. Require effects beyond a single backbone and on difficult poses in an external dataset. [DUNE](https://arxiv.org/abs/2503.14405) already distills heterogeneous 2D/3D/human features, and [BinParam](https://www.sciencedirect.com/science/article/pii/S0925231226009574) includes feature distillation for efficient parametric reconstruction. Adding feature MSE alone is therefore insufficient novelty.

Main risks: fitting privileged annotations does not guarantee the monocular teacher knows the same answer, and sensitivity selection may retain unstable teacher directions. Teacher accuracy, descriptor compression and reliability calibration must be measured. This is my first choice for improving pose accuracy at fixed deployed architecture, provided the offline budget is acceptable.

**3. A single inexpensive correction that uses 2D evidence only where it constrains 3D.**

Hypothesis: the model predicts both 2D locations and a body model, but the deployed 2D evidence never explicitly corrects the body. A generic reprojection correction can improve pixels while worsening depth. Learn a correction restricted by which pose directions the available observations can actually determine.

Use calibrated 2D uncertainty, residuals between predicted image joints and projected MHR joints, the current pose, and full camera information. During training, the projection/kinematic Jacobian identifies well-observed versus ambiguous directions. A damped small correction should use image residuals in the former and preserve the learned prior in the latter. Distill that operation into a compact module predicting, for example, 16–32 correction coefficients. Runtime uses one encoder pass, one correction module and the necessary rig evaluation; no test-time autograd or iterative diffusion. Calibrate uncertainty separately: SimCC's fixed-width Gaussian training targets do not automatically provide calibrated uncertainty.

The Jacobian and damped-update formulation are training tools here, not an assumption that a full 204-parameter solver is free. Profile the actual correction plus FK. Set a design cap of 0.5M extra parameters and 10% additional median and p95 person-pipeline latency, including geometry decoding. Stop or redesign if the cost exceeds that cap. Numerical stability and ONNX compatibility must be demonstrated.

The claim is safe, calibrated use of available evidence under occlusion and camera error at a tightly bounded compute cost. Compare against an equal-size unconstrained residual MLP, one ungated correction step, reprojection-loss tuning, and an existing refinement method. Evaluate PA-MPJPE and absolute error together; merely improving reprojection is insufficient. [PyMAF](https://openaccess.thecvf.com/content/ICCV2021/papers/Zhang_PyMAF_3D_Human_Pose_and_Shape_Regression_With_Pyramidal_Mesh_ICCV_2021_paper.pdf) already feeds alignment evidence back into regression; [TokenHMR](https://arxiv.org/abs/2404.16752) studies the 2D/3D tradeoff; [Multi-HMR 2](https://arxiv.org/abs/2606.14841) addresses camera-centric recovery. A residual head, uncertainty weighting or camera conditioning alone is not sufficient novelty.

Main risk: monocular depth ambiguity cannot be solved by algebra or confidence alone. The correction must fall back to its prior when evidence is insufficient, and a lower 2D error cannot guarantee a lower true 3D error. Demonstrate failure detection and robustness rather than claiming a universal guarantee.

**How to decide whether any direction deserves a full paper.**

First establish a corrected baseline with config/export parity, stable bounds, correct crop geometry, clean sequence manifests and fixed adapter provenance. Preserve an old-compatible configuration for historical comparisons. Run ordinary fixes as baseline work; do not count their gains as the proposed method's novelty.

The documented new-run safeguards `--cliff-focal`, `--bound-scales` and `--anomaly-safe-fallback` still default to off. Neither preset automatically enables all of them. Explicit run configuration is necessary, and the export/evaluation defects above must be repaired before a bounded, focal-aware run can be judged through all entry points.

Screen each direction independently on matched data, initial weights, sample counts and optimizer-update budgets using validation only. Use paired seeds for early elimination, then at least three complete seeds for a promising direction and more if variance remains high. Bootstrap by sequence/person rather than treating adjacent frames as independent. Compare against the corrected baseline and the simplest non-novel alternative.

As a project decision threshold—not a CVPR rule or a predicted outcome—seek about 10% lower primary 3D error (roughly 4 mm if the corrected baseline remains near 42 mm), replicated on at least one external benchmark, with hand/surface quality preserved and the compute caps met. A smaller aggregate gain can still be meaningful if the paper establishes a substantial, general failure-mode improvement with strong evidence. Fix the threshold on validation before inspecting final test results.

For public comparisons include [SAM 3D Body](https://arxiv.org/abs/2602.15989), [Fast SAM 3D Body](https://arxiv.org/abs/2603.15603), [FastHMR](https://arxiv.org/abs/2510.10868), and relevant strong pose baselines such as [NLF](https://arxiv.org/abs/2407.07532), subject to matched data and evaluation protocols. Fast SAM 3D Body already reports up to 10.9× end-to-end acceleration; a lightweight SAM student by itself is not a sufficient novelty argument. Separate network-only timing, rig decoding and detector-inclusive timing on identical hardware and precision.
